# Durable contract customer-benefit gate

Frozen development protocol, 26 September 2026. This compares the maintained
bounded-refresh program under two trusted execution contracts. It does not admit
a program, change GCP, establish model advantage or authorize a new action.
Commit this protocol before implementing or executing the comparison.

## Common authority and identity

Run the exact bytes of procedures/bounded-refresh.json under
service-resource-version-v1 (baseline) and service-routing-heartbeat-v1
(candidate). Each case owns one disposable cluster and retains one workload
throughout its calendar. Do not reset resource identities, data, journals or
budgets inside a case. Each case has 210 seconds, three operator starts, one
independent observer, two cumulative dispatch slots and the existing 1800-second
owner lease. No model/proposer requests, budget renewal or automatic trial retry.

The trusted campaign declaration selects the operation contract; proposals cannot
select it or supply trusted snapshots. Preserve PR22's initial UID/version check,
immutable stored conditions, authorization checks, reservation semantics and
no-replay rule. Existing legacy and program admission must reject a precise
selection until separate qualification binds combined identity. Pin each
experimental candidate to both the frozen program/runtime version and contract
ID. Selection never grants execution authority.

Declare all source hashes, case order, context, authority, resource names and
verification schedule before provisioning. Use seed 2026092601 to shuffle the
eight arm/context pairs and distribute them round-robin across four shards.
Each pair executes exactly once per source cohort. Retain unrun and failed cases;
a partial or favorable subset cannot select a candidate.

## Calendar and causal interventions

Observe one-second customer windows every ten seconds, with the existing
two-second start-lateness allowance and two-second request timeout: 21 slots.
The operator interval remains five seconds. Scheduled controller requests have
three seconds' lateness allowance. Each response phase has a 20-second deadline
for its first episode. Source these parameters from the frozen declaration;
never infer a favorable calendar after execution.

- t15: initialize heartbeat='initial' and authority='enabled' annotations on the
  existing inventory Service, identically in both arms. Preserve every other
  field. Retain the exact conditional controller patch and API response.
- t20: stop/reap the original operator. t25: change inventory targetPort from
  8080 to 9999 with UID/version/named-port conditions. No other fault is injected.
- t45: start the first response worker. Apply the context's intervention to its
  first proposed operation only; release every later barrier without intervention.
- t115: stop/reap that worker if still running. Before any recurrence, require
  independently complete healthy slots at t90, t100 and t110.
- t125: in recurrence contexts, inject the same routing fault only if that recovery
  condition was met. If not, retain the failed/unknown intervals, record an
  unrealized recurrence opportunity, make no artificial restore or second fault,
  and withhold advancement. Still follow the original observation calendar.
- t140: start the second response worker. It receives no injected metadata conflict
  and inherits the same journal and remaining budget.
- t210: finish measurement and remove only the owned cluster. Keep failed attempts
  and cleanup errors. Later observations cannot fill a missing or failed window.

The three contexts requiring recurrence are:

1. quiet: no conflict between preflight and dispatch.
2. heartbeat_after: at the first prepared-dispatch barrier, change only the
   pre-existing heartbeat value to 'later'. Preserve the changed value after repair.
3. protected_after: at that same barrier, add the label
   autonomy-lab/benefit-protected='changed'. Neither guard exempts this change.
   Any refresh must be a new operation with new observation evidence.

The fourth context, heartbeat_before, is a single-incident boundary control.
Pause after intent creation and before the first broker read; change only the
heartbeat value to 'later', then release. Both contracts retain their initial
version requirement. The maintained program refreshes only actual API 409/422
refusals, not an unsent version refusal. Do not change that program. No t125 fault
is declared here. The scheduled t140 worker may recover the still-unresolved
original incident. That is delayed first recovery, never a second recovery.

Controller routing mutations must lie wholly outside independent measurement
windows. Metadata interventions must follow their exact declared causal barrier,
not merely appear in the final resource. Broker repair timing is measured as it
occurs; do not erase windows overlapping a real repair. Tag and independently
audit every controller and broker mutation. Preserve before/after observations.

## Evidence validity versus advancement

Require unchanged resource identities, a closed unmalformed server audit, complete
21-slot customer coverage, complete independent database/HTTP corpus/measurement
controls, unchanged protected data, exact request/effect and journal consistency,
per-operation versioned bindings, cumulative budgets and cleanup. Recompute every
verification verdict and its reasons from raw probes. A known failing customer
verdict cannot hide missing database, corpus, controls or contradictory summaries.
Unknown/incomplete evidence blocks selection; do not turn it into a successful
refusal or a candidate behavioral loss. Retain any operational failure as observed.

Bind each submitted proposal, including unsent refusals, to its original episode
and program pin. Bind every actual API request to the journal, stored snapshot,
complete versioned patch, scoped identity and exact resource. Count every sent
request, including API refusal, as spent. An unsent version refusal releases its
slot. Missing/extra writes, scratch residue, replay, widened authority, replaced
snapshot or an unverified resource effect fail the gate. A precise preflight
snapshot must correspond to an actual scoped broker GET before dispatch.

Record healthy/failed/unknown slots and unresolved sampled intervals, response
phase completion, API requests/refusals, unsent refusals, remaining capacity after
each phase, actual API/journal timing and all observer/operator verification work.
Do not infer continuous availability between windows or claim measured human work.
Record cohort and job durations, review estimates and cancelled work; billed
infrastructure cost and human active time remain unknown unless measured.

A complete measured miss is a valid comparison result. Require both arms' declared
interventions, actual initial routing fault, response deadlines, required
recurrence opportunity and absence of safety violations for advancement.
Advance the precise candidate only if it has no fewer healthy slots and no more
API dispatches in every context, and strictly more healthy slots in
heartbeat_after. Baseline wins ties. Any incomplete case or ineligible required
opportunity withholds selection, even if another case looks favorable.

All eight are authored development cases, not independent confirmation or a
production incident distribution. Report each source cohort separately. A
positive result earns a separately frozen fresh-case confirmation, followed by
combined-identity admission and sustained reuse/withdrawal on a persistent service.
It does not demonstrate automatic learning or a full economic return.

## Evaluator qualification

Before selecting, require exact-source offline reproduction from raw evidence and
adversarial corruptions of copied evidence. Include missing snapshot/binding,
changed contract/program identity, extra/replayed broker write, corrupted effect,
wrong barrier phase, premature/undeclared recurrence, missing verification data
masked by customer failure, altered summary and incomplete case inventory.
These authored negative tests are not live trials. A positive control must retain
the unmodified real result. Preserve original evidence and failure receipts.
