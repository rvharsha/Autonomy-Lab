# Final-slot contract confirmation

Prospective protocol, 26 September 2026. Commit before implementation or execution.
The purpose is to finish one bounded confirmation decision, then consider combined
admission and persistent operating cycles. No extra metadata variations are needed
merely to accumulate successes. A pass is an engineered improvement under bounded
authority, not a model-discovery, autonomous-learning or production-reliability claim.

Keep the PR23 program/runtime and both combined contract identities in
`experiments/contract_confirmation/runtime-pin.json` exactly unchanged. The prior
PR24 cohort remains development evidence with original selection null. Its failed
gate must not be overwritten or silently rerun. Shared external controller and

The retained-corpus inventory in `docs/validation/final-slot-novelty.json` covers

PR21-22 used independent single-operation cases. PR23-24 placed contention in the
first response, or a heartbeat after its acknowledgement but before recurrence.
No retained persistent comparison injected metadata contention in the second
response, or a protected controller change between recurrence and that worker's
initial observation. The new combination is the budget/incident phase, not a new
heartbeat spelling or unseen component behavior. Cases are authored prospectively
by the same implementer; they are not a production sample or independently designed.

## One fixed six-case cohort

Both arms use the maintained bounded-refresh program, one workload for 210 seconds,
21 independent sampled customer windows, three operator starts and two cumulative
dispatch slots. No model calls, runtime changes, extra grants, resets or retries.
The trusted controller selects legacy versus precise; an agent cannot choose it.
Use seed 2026092603 to shuffle six named cases into three round-robin shards.
Freeze all case order, source hashes, evaluator, timeouts and controls before live
execution. One attempt per case; preserve unrun, failed and incomplete attempts.

Common calendar: fixture t15, stop initial operator t20, routing fault t25, quiet
first response t45, stop that worker t115. Complete healthy observations at
t90/t100/t110 are required for recurrence at t125. No artificial repair may make
an unrealized recurrence possible. Second response starts t140; measurement ends
t210. Every first repair must be one acknowledged, audited dispatch with one slot
remaining. Its journal and spent budget must persist into the second response.
Each response's first episode must finish within 20 seconds. Controller schedule
lateness remains at most three seconds. Routing faults cannot overlap independent
measurement windows. Require complete evidence, not just a claimed healthy verdict.

Run each context in legacy and precise arms:

1. `heartbeat_final`: on the second response's first prepared-dispatch barrier,
   change the existing heartbeat value from initial to tick-1. Preserve its latest
   value on acceptance. No other metadata conflict is injected.
2. `protected_final`: at that same barrier, change heartbeat to tick-1 and add
   `autonomy-lab/confirmation-protected=changed` in a separate audited conditional
   request. The protected field remains consequential even when rejecting it costs
   the final repair opportunity. A refreshed proposal cannot obtain a third slot.
3. `protected_before`: add that protected annotation at t135, completing before the
   second worker starts and observes the Service. Do not inject a barrier conflict.
   Protecting a snapshot is not a permanent prohibition on a field having changed
   before preparation. Both arms must operate from the actually observed state.

Prove causal placement against real API reads, worker/episode IDs, durable intent,
prepared conditions and controller responses. Independently bind the quiet first
acknowledgement, spent slot, recovery proof, recurrence and second operation.
Require exact full-resource effects, all Service writes accounted, no scratch
residue, and complete protected-data/customer/control verification. A successful
API response alone is not recovery. Preserve the existing current-value semantics;
this experiment does not claim that a heartbeat exception proves absence of history.

## Qualification and advancement

Prequalify corruption builders before live execution, including absent, empty and
existing optional metadata maps. Use archived real development evidence for shared
checker regression; authored checker inputs are never live results. Every negative
control must reach its declared rejection. A crash or unrelated refusal cannot pass.
Challenge phase/operation placement, acknowledgement and prior budget, late early
change, protected effects, omitted/reordered/intermediate writes, missing bindings,
extra requests, missing recovery proof, incomplete customer/database/corpus evidence,
changed program and case inventory. Retain exact control/source identities.

All six cases must complete and be eligible and authority-conformant. Precise must
have no fewer healthy samples or more actual dispatches in any context, with a
strict healthy-sample gain in heartbeat_final. Ties or a regression retain legacy.
Unknown measurements, unrealized recovery, missed deadlines, failed cleanup or
incomplete qualification withhold selection. No numerical outcome is assigned.

Each shard has at most two campaigns: provision each within 180 seconds, cap case
execution at 25 minutes, and reserve a separate 35-minute job envelope for setup
and evidence upload. Cancellation/host loss remains incomplete evidence. Freeze
once and run one bounded cohort. Changes prompted by its results retire that cohort
to development; no favorable subset or silent fresh retry is permitted.

Selection grants no execution authority. A pass supports a separately qualified
admission binding exact program/runtime and execution contract. Adding that code
creates a new runtime identity; old approval cannot inherit it. Then operate one
workload across explicit budget cycles with withdrawal and full work accounting.
A failed comparison retains the baseline and changes the next engineering decision;
it must not cause indefinite searches for favorable metadata examples.

Report healthy/failed/unknown samples, actual dispatches and spent/remaining slots,
completed verification work, episodes lacking completed verification records,
elapsed evaluation and review work, including failed attempts. Full request cost,
billed infrastructure and human active time remain unknown on this frozen runtime.
