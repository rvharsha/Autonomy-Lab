# Shortest test of the update loop

27 September 2026. Frozen development protocol; results are not assumed.

The objective is an operator that improves from experience under independent
evaluation and bounded authority. More execution controls alone do not establish
that improvement. Production admission and durable budget grants remain necessary
for sustained reuse, but they need not precede this disposable, bounded test.

## Question and claim boundary

Can an automatic selector turn reproduced operating evidence into an exact
candidate and have a later independent evaluation establish its bounded benefit?
Use the existing two human-authored execution contracts with the same maintained
program. This is an exhaustive finite selector, not model synthesis. The earlier
eight-program search is closed with no challenger; it is not repeated here.

The original legacy contract is the starting operator and no-update comparator.
The maintained precise contract is the strongest available engineering comparator.
The automatically selected contract is a third arm, executed separately even when
its bytes match a comparator. All arms have the same routing mutation scope and
two-dispatch limit. Their conditional-write semantics deliberately differ; a
benefit cannot be attributed to better reasoning under identical semantics.

These are known development contexts, including already observed confirmation
cases. Fresh execution does not make them hidden tests. A successful result would
demonstrate automatic selection and prospective execution of a known configuration
update. It would not demonstrate autonomous discovery, generalization, model value,
production promotion or a continuously evolving service. If the selected policy is
identical to maintained precise automation, favorable measurement noise cannot be
reported as an incremental strategy advantage.

## Freeze, run and independently reproduce

1. Retrieve the five original ZIPs pinned by ID and SHA-256 in
   `experiments/shadow_selection/training-artifacts.json`. Reproduce all eight
   PR26 customer-benefit development cases from raw probes, API audit, operation
   records and exact runtime dependencies, including the existing negative controls.
   Uploaded summaries alone cannot select a contract. Preserve the historical
   acquisition cost; using old observations does not make training free.
2. Apply the existing development selection rule: complete eligible evidence,
   no customer-window or dispatch regression in any context, strict gain in the
   heartbeat-after context, and legacy wins ties. Ineligibility stops the loop.
   Freeze the full selection, its input digests, source hashes, time, all nine
   subsequent cases and seeded order before provisioning any new workload.
3. Execute each role once in each known final-slot context: heartbeat interference,
   heartbeat plus protected change, and protected change before fresh preparation.
   Use three independent shards and nine distinct workload identities. Preserve
   the existing 210-second calendar, 21 samples, three operator generations, two
   dispatches, verified first recovery and one remaining slot. Each arm receives
   its own real execution; never reuse another arm's measurements.
4. Reproduce training again and require the identical choice. Reconstruct every
   new outcome from complete evidence and the existing full mutation auditor.
   Require all workload windows to follow the frozen selection time. Apply the
   existing 24 final-slot evidence corruptions to copies of new measurements;
   crashes and unrelated refusals never count as successful controls.

All nine cases must be measurement-valid and authority-conformant. All must be
eligible for a benefit decision. A bounded update is observed only if selected
has no fewer healthy windows and no more dispatches in every context than legacy,
with strictly more healthy windows in at least one. Show every context and the
comparison with maintained precise automation. A complete negative result closes
this mechanism attempt; incomplete evidence withholds a benefit decision.

No automatic retry, new sample replacing a failure, threshold change after seeing
results, admission, model call or production deployment. Source corrections require
a separately retained cohort. Workflow launch is limited to the initial opening
of the dedicated PR branch; retries refuse before new experiment execution.

The nine calendars require 31.5 workload-minutes before setup, cleanup and review.
Three shards have 30-minute execution caps inside 40-minute jobs. Report wall time,
actual API requests, verification work and review usage separately. Billed compute,
human active time and full net benefit remain unknown unless directly measured.

## Decision after this test

If the loop works and matches maintained automation, retain the simpler finite
selector and report that boundary. Do not add an LLM to relabel a known catalogue
choice as discovery. A subsequent learning-value experiment needs a concrete
operating gap beyond this catalogue, an experience ablation, strong maintained
automation, prospectively sealed causal cases and all rejected-candidate costs.
Define that gap before investing in another proposer or action family.

Precise-contract admission and persistence across explicit budget grants remain
the path to live sustained reuse. This experiment changes their sequencing as
dependencies of a shadow mechanism test, not their requirements for deployment.
